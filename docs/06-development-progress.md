# 开发进度 · 2026-10-24

## 本轮交付

完成从浏览器本地存储原型到 PostgreSQL 真实预订闭环。当前入口为根目录 `npm run dev`，静态原型保留在 `prototype/`。

技术选择：Node.js 22 + TypeScript + Express 5 + PostgreSQL 17 + Zod。数据库复用 `~/jonge/infra`，业务独占 `spaceflow` 库。运行账号 `spaceflow_app`，迁移账号 `spaceflow_migrator`；连接信息不提交。

前端沿用现有 HTML/CSS/JavaScript 和 SVG 编辑器，避免在核心规则验证前重写界面。Konva 和日历组件尚未作为应用依赖；原先的选型倾向不等于已采纳。

## 业务决定

- 单次预订范围为未来一年内，同日开始结束，业务时区固定 `Asia/Shanghai`，数据库保存带时区时间。
- `pending`、`confirmed` 参与排除约束，区间 `[start,end)`，相邻预订允许。
- 待审批时段占位到提交后 24 小时或使用开始时刻，以较早者为准；后台每 30 秒回收，读写预约时也主动回收。
- 管理员审批全部会议室；管理员也可以预订专属会议室。员工只能取消自己的有效申请。
- `disabled`、`maintenance` 保持可见但禁止新预订；`hidden` 对员工隐藏。状态变更保留已有预订。
- 隐藏信息仅本人和管理员可读取；其他员工的响应完全省略联系人、联系方式，主题替换为占用信息。
- 布局保存显式提交，以版本号避免覆盖；不将未保存编辑写入浏览器存储。
- 周期预订暂不开放，避免保留无法执行的开关。

数据库约束参考 [PostgreSQL 范围约束文档](https://www.postgresql.org/docs/17/rangetypes.html#RANGETYPES-CONSTRAINT)。异步接口错误处理使用 [Express 5 错误处理机制](https://expressjs.com/en/guide/error-handling/)。
