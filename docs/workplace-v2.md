# SpaceFlow 2.0 — 企业办公空间管理
## 产品定位
不是 CAD、BIM 或智慧楼宇控制系统，而是企业行政的办公空间台账、可视地图及员工自助服务。空间布局表达相对位置、形状、朝向即可，不承担施工、消防或精确面积测算职责。

## 产品结构
员工：空间地图（园区/楼栋/楼层、搜索、工位和会议室详情）、会议室发现、日程、我的预订。管理员：地图及布局、园区楼栋楼层台账、工位和人员分配、会议室和审批、组织和统计。
园区展示建筑分布，建筑展示可选择楼层的分层沙盘，楼层展示房间、区域、工位、公共设施；所有视图均可从列表选择，3D 不是唯一访问方式。使用轻量轴测视角和柔和中性色，状态图层突出业务信息；避免大屏、光效和漫游。
## 核心业务流程
1. 新建园区，在既有楼栋/楼层管理中录入建筑与楼层，分配楼栋到园区并调整其平面位置。
2. 管理员在楼层地图绘制矩形区域、墙体、门、设施；通过行列与编号批量布置工位；修改位置、尺寸和朝向。后续支持底图描摹、自由多边形、组合和复制、撤销/重做。
3. 会议室关联已有会议室 ID，几何变更不修改预订或审批。员工点击地图中的会议室进入原详情和预订流程；没有绑定的房间仅是布局。
4. 工位绑定现有员工，显示分配而不是实时在岗；员工按工位或姓名搜索。后续实现分配历史、生效时间、批量导入、搬迁方案与部门分区。
5. 地图显示基础布局、分配、选定时段会议室状态。后续增加部门图层和真实利用率分析，不能将预订或分配率冒充传感器占用率。
## 实现边界及数据
继续 React/Express/PostgreSQL 模块化单体。使用相对坐标 100×70 的简化平面，3D 采用 Three.js 程序化图形，墙高与家具高度为视觉默认值。不使用远程模型/CDN。一个布局由同一对象集合产生 2D/3D；对象稳定 ID，房间绑定独立业务 ID。
增量迁移保留原表与预订排除约束；旧楼栋归默认园区。旧楼层初始为空，管理员在未布置会议室列表中快速放置原有资源，不伪造实际布局。楼层地图单独请求，写入管理员限定、版本乐观锁、历史快照与审计；隐藏会议室不得通过地图或搜索泄露。布局与旧房间模板互不覆盖，已有会议室需要显式绑定位置。既有目录仍管理楼栋、楼层和会议室。
## 交付及验收
首个正式增量：园区创建/改名、建筑归属和位置、楼层下钻、2D/3D、基础编辑、批量工位、人员分配、绑定会议室、按时间通过独立服务端接口查询可订状态、持久化和权限。
后续产品完善：底图导入与自由区域、快捷键/撤销/复制、独立草稿和正式发布、部门区域/分配历史、跨层搬迁、统计报表、管理范围授权、SSO。保留原测试，新增校验和接口权限测试，真实浏览器验证大楼层操作、地图点击、移动端、WebGL 降级和旧预订回归。首个增量不宣称后续功能已经完成。

## 第二批实现
正式地图与服务器草稿分离；草稿保存、发布、删除及历史载入；发布时重新验证跨层工位唯一性。编辑专用参考底图、自由区域顶点绘制、撤销重做、部门区域与工位关联、批量人员分配、同层工位调动；全园区已发布地图搜索及楼层统计。未完成跨楼层一次性搬迁及底图 PDF 直接解析。

## 第三批实现
已发布地图提供独立的单人及批量跨楼层工位调动。服务端以一个事务清除原工位、设置目标工位、记录涉及楼层的新版本与审计；存在未发布草稿或目标已被占用时拒绝操作，不静默覆盖。支持释放工位。此功能不依赖 3D 几何精度。

## 园区地图
园区可直接编辑建筑位置、宽深、朝向，以及道路、绿化、停车区和广场。所有对象采用相对坐标并由同一数据生成平面及三维地图。园区整体布局原子保存、版本冲突检查，不影响建筑和会议室业务 ID。
