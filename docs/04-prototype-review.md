# 04 · 可交互原型使用与评审脚本

## 启动

直接打开仓库中的 `prototype/index.html`，无需依赖安装。也可以运行 `python3 -m http.server 8080 --directory prototype`，打开 `http://localhost:8080/`。首次使用包含 6 间虚构会议室、两栋楼及当天的示例占用。

UI 是偏克制的空间管理工作台风格：深绿色左侧导航、浅色内容区、清晰的会议室内部平面示意，不沿用市场上通用 OA 表格外观。桌椅、门窗和设备为示意组件，不代表工程精度。

## 路径 A · 会议室发现与预订

1. 在「空间发现」调整楼栋、楼层、日期、时间、容纳人数及设施条件，确认候选数量会变化。
2. 打开「青岚会议室」详情，查看桌椅、门窗、屏幕和已有预订。默认日期当天 10:00–11:00 存在冲突。
3. 点击「预订会议室」，填写主题、时间和联系人；先尝试冲突时段，观察冲突提示，再尝试一个空闲时段。
4. 若选择「栖云」，因其采用审批模式，提交后会显示「待审批」；不模拟实际审批人操作。
5. 选择隐藏详情，回到会议室详情及日程时，只保留占用信息，隐藏主题与联系人。
6. 在「我的预订」取消自己的预约，确认相应时段会被释放。

## 路径 B · 多会议室日程

1. 进入「预订日程」，查看会议室 × 08:00–18:00 占用矩阵。
2. 点击空白格，将会议室、日期与时段带入预订弹窗；点已占用格则进入对应会议室详情。
3. 修改日期，确认随日期切换到对应的模拟记录。

## 路径 C · 管理端布局编辑

1. 进入「布局编辑器」，选择不同会议室，观察其布局模板不同。
2. 点击「会议长桌」「座椅」等组件新增元素，在画布上拖动。
3. 选中元素后通过右侧属性面板修改 X/Y 坐标和旋转，尝试复制、删除、撤销。
4. 点击「保存布局」，刷新页面后继续查看修改后的会议室内部布局。
5. 点击「导出布局 JSON」，检查 `schemaVersion`、坐标系及元素属性；使用「应用默认布局模板」可恢复模板。

## 路径 D · 每间会议室的独立规则

进入「预订规则」，将一间会议室切换为「需要审批」或「仅管理员可预订」，另可切换周期性预订开关。回到详情页，应该看到规则展示变化。注意周期性开关仅展示配置结果，**原型不能创建真正的 RRULE 序列**。

## 功能完成度矩阵

| 能力 | 原型状态 | 备注 |
|---|---|---|
| 建筑/楼层/人数/设备筛选 | 可交互 | 基于浏览器示例数据 |
| 会议室详情/示意平面图 | 可交互 | SVG 只读渲染 |
| 占用矩阵/时间预填 | 可交互 | 小时粒度展示；时间检测为分钟字符串区间 |
| 单次预订/取消 | 本地模拟 | 浏览器 localStorage，非多人系统 |
| 信息隐藏 | 本地模拟 | 不等于服务端权限控制 |
| 审批模式/周期性配置 | 模拟配置 | 没有真实审批和周期执行 |
| 画布拖拽/组件增删改旋转 | 可交互 | SVG pointer 交互；React Konva 另有隔离 PoC |
| 模板重置/布局导出 | 可交互 | JSON 仅供模型验证 |
| 用户/部门权限与 SSO | 未做 | 一期后台业务需实现 |
| 数据库并发/审计/通知 | 未做 | 需后端及 PostgreSQL 测试 |
| 手机画布编辑 / 无障碍 | 未验证 | 原型优先桌面 |

## 收集反馈的关键问题

- 同时看楼层位置和筛选条件，是否比纯列表更直观？楼层筛选是否足够明显？
- 详情页在布局与预约信息之间的内容分配是否合理？
- 预订的常见动作应放在列表卡片上还是详情页？
- 编辑器内置组件是否足够，管理员有没有必要调整实际尺寸？
- “隐藏预订详情”和“会议室隐藏”的文案是否足够区分？

## 演示注意

示例用户名、会议主题与手机号均为虚构；不能存放真实敏感数据。浏览器清缓存会丢失自定义布局和预订。若需完整重置，进入「我的预订」点击「重置演示数据」。
