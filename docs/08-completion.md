# 本轮交付与验收

## 完成内容

| 领域 | 当前能力 |
| --- | --- |
| 空间层级 | 楼栋 → 楼层 → 会议室；新建、改名、排序、移动归属；有下级对象时禁止删除 |
| 会议室管理 | 左侧层级树筛选；新增与编辑时选择楼层；改名同步；不上传真实照片，不绘制整层地图 |
| 预订修改 | 主题、联系信息、隐私、房间和时段；本次或选中项及之后的有效预订；版本校验与冲突整批回滚 |
| 审批 | 改期或换房进入需要审批的房间后重新申请；仅改文字不延长审批占位期限；过期申请不能复活 |
| 周期 | 每天、每周指定星期、每月同日，支持间隔；月末不存在的日期跳过而不顺延；最多 52 次且限定未来一年 |
| 日程 | 日/周视图、日期切换、资源分页、点击预订、拖拽打开改期确认；普通用户只读其他人的日程 |
| 布局 | 拖动、角点缩放、数值尺寸、旋转、网格吸附、撤销、JSON 导入导出、自定义模板、最近 50 个历史版本载入与保存 |
| 通知 | 站内通知；事务邮件队列、失败退避重试和固定邮件标识；设置个人通知邮箱 |
| 工程 | 多阶段镜像、非 root 运行、只读文件系统、健康检查、自动重启、本地 HTTPS、GitHub Actions 验证流程 |

## 关键规则

- 迁移保留原会议室标识、预订和布局。历史文本位置自动归入楼栋与楼层；会议室调整归属不迁移或删除预订。
- 可见/可订规则与楼栋层级独立，权限仍在会议室级生效。
- 修改范围“本次及之后”从选中的那一条开始，只处理尚未开始的有效预订；此前记录、取消例外和被跳过日期不复活。日期与时间按统一差值移动，保留原周期间隔。
- 周期系列保留原始规则、单次例外及变更记录。日期使用办公地 `Asia/Shanghai`，不支持跨日预订。
- 同系列重排先在事务内释放受影响占位，再应用全部修改。任何冲突导致整批回滚；事务提交后只产生最终状态通知，不产生中间“取消”通知。
- 布局导入仅接受版本 1、600×390 坐标系、白名单组件、有限数值和唯一元素 ID。载入模板、历史版本或导入后，需要点击保存才对其他用户生效。
- 邮件写入与预订同事务，发送在后台进行；SMTP 失败不影响预订。失败最多重试 8 次，间隔递增；网络故障下按至少一次投递处理。

## 已验证

- 24 项数据库/规则/邮件集成测试，包括 100 个并发重叠预订、改期回滚、历史保留、审批期限、月末周期、布局历史和权限。
- 100 间资源、1000 条日程数据下，20 间资源的一页查询返回 200 条日程；本机测得约 5 毫秒。该数字只代表当前本机测试条件。
- 三套 Chrome 验收，涵盖管理、权限、层级、周期冲突、预订修改、拖拽改期、布局导入/历史恢复与账户操作；小屏层级页面可操作。
- axe 对层级管理、布局编辑和周日程执行 WCAG 2 A/AA、2.1 AA 自动扫描，零违规；同时保留数值编辑和按钮入口作为拖拽替代。自动扫描不代替完整人工读屏审计。
- 本地 SMTP 接收端收到真实 SMTP 消息；失败重试后标记已发送，再次执行不重复发送。
- 全新临时数据库执行全部迁移与初始化，6 间会议室均有楼层归属和初始布局版本，且不覆盖本地账号文件。
- Docker 镜像构建、容器健康状态与本地 HTTPS 证书校验通过；备份恢复在独立临时数据库验证。

## 运行与部署

```bash
npm ci
npm run setup:local
npm run deploy:local
```

继续使用 `http://127.0.0.1:3080`。应用容器复用 `~/jonge/infra` 的 PostgreSQL，并在退出开发会话后继续运行；Docker 运行时恢复后按 `unless-stopped` 策略重启。

```bash
npm run deploy:https
```

本地 HTTPS：`https://localhost:3443`，使用 `.tls/` 下的项目证书，未修改系统信任设置。对外部署时使用实际域名的可信证书，并将 `APP_ORIGIN` 设置为真实 HTTPS 地址。地址和认证配置见 `.env.example`。

开发调试：先停止占用同一端口的应用容器，再运行 `npm run dev`。

```bash
docker compose --env-file .env.container stop app https
npm run dev
```

## 邮件配置

未配置 SMTP 时站内通知正常工作，不尝试外发邮件。实际邮件外发需要提供服务器连接信息：

| 变量 | 用途 |
| --- | --- |
| `SMTP_URL` | 本机运行后端时的 SMTP 连接地址 |
| `CONTAINER_SMTP_URL` | 应用容器可访问的 SMTP 地址 |
| `MAIL_FROM` | 发件地址 |

配置后重新部署。用户在“账号设置”填写通知邮箱，管理员也可在账号管理维护邮箱。
